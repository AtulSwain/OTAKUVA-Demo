# OTAKUVA — Canonical Data Architecture

---

## 1. Architectural Invariant

OTAKUVA is an anime discovery, tracking, rating, and culture platform ("Track what you watch.").

```
JIKAN / EXTERNAL PROVIDERS
        ↓
PROVIDER ABSTRACTION LAYER (AnimeDataProvider)
        ↓
RATE LIMITER & THROTTLING (800ms Token Bucket)
        ↓
IN-FLIGHT REQUEST DEDUPLICATION (inFlightRequests Map)
        ↓
TIERED CACHE (24h In-Memory Cache)
        ↓
RAW RESPONSE VALIDATION & NORMALIZATION
        ↓
CANONICAL ENTITY IDENTITY RESOLUTION
        ↓
DEDUPLICATION & EDITORIAL OVERRIDE PRESERVATION
        ↓
CANONICAL DATABASE (PostgreSQL / SQLite via Prisma)
        ↓
OTAKUVA INTERNAL API (REST & Server Actions)
        ↓
FRONTEND (Zero Direct Provider Coupling)
```

## 2. Canonical Entity Data Models

### A. Primary Entity: `Anime`
- **Internal ID**: Authoritative CUID (`id`) generated by OTAKUVA.
- **Slug**: Normalized, URL-safe title slug (`slug`), e.g. `/anime/monster`, `/anime/attack-on-titan`.
- **Multi-Language Titles**: Stored in `AnimeTitle` records (`official`, `english`, `japanese`, `romaji`, `synonym`) with a resolved `canonicalTitle`.
- **Metadata**: `synopsis`, `background`, `type` (TV, MOVIE, OVA, ONA, SPECIAL), `status` (AIRING, FINISHED, UPCOMING), `episodes`, `duration`, `season`, `year`, `airedFrom`, `airedTo`.

### B. Provider Mapping: `AnimeExternalId`
- Maps `(provider, externalId)` -> `animeId`.
- Unique constraint: `@@unique([provider, externalId])`.
- Allows multiple external providers (Jikan/MAL, AniList, Kitsu) to link to the single canonical OTAKUVA anime record.

### C. Episodes: `Episode` & `EpisodeExternalId`
- Identity: `(animeId, number)`. Unique constraint: `@@unique([animeId, number])`.
- Metadata: `title`, `titleJapanese`, `synopsis`, `airedAt`, `duration`, `filler`, `recap`, `imageUrl`.
- Provider ID: `EpisodeExternalId` maps `(provider, externalId)` -> `episodeId`.

### D. Studios & Producers: `Studio`, `Producer`, `AnimeStudio`, `AnimeProducer`
- Canonical `Studio` records with normalized names and slugs (`UNIQUE(slug)`).
- Relational mapping via join tables (`AnimeStudio`, `AnimeProducer`) with `isMain` flag.

### E. Creators & People: `Person`, `AnimeStaff`, `VoiceRole`
- `Person` represents the human creator / actor.
- `AnimeStaff` links `(animeId, personId, role)` (e.g. Director, Series Composition).
- `VoiceRole` links `(characterId, personId, language)`.

### F. Characters: `Character`, `AnimeCharacter`
- Canonical `Character` records with `name`, `nameKanji`, `about`, `imageUrl`.
- `AnimeCharacter` links `(animeId, characterId, role)` (MAIN, SUPPORTING).

### G. Media & Images: `MediaAsset`
- Manages posters, backdrops, banners, and character avatars.
- URL validation, format checks, corrupted token filtering (`undefined`, `null`, placeholders), and deterministic SVG artwork fallback generation.

---

## 3. Ingestion, Synchronization & Conflict Resolution

1. **Identity Resolution**: Checks incoming external ID against `AnimeExternalId`. If not found, checks exact normalized titles and release year before creating a new canonical record.
2. **Editorial Overrides**: Preserves admin edits (`EditorialOverride`) across automatic sync runs.
3. **Partial Ingestion**: If basic anime metadata succeeds but optional enrichment (characters/news) times out, the anime remains available and the enrichment task is queued for retry.
4. **Provenance**: Every record tracks `lastSyncedAt`, `externalSource`, and `metadataHash`.
