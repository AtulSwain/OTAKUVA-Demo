# OTAKUVA audit — 2026-09-11

Phases 1–3 (audit, root cause, plan) for the production-quality pass. Every
finding below was checked against the code or the dev database in this
session; nothing is carried over from earlier reports without re-checking.
Several earlier reports (`OTAKUVA_DATA_INTEGRITY_REPORT.md` in particular)
claim things that turned out not to hold — see §3.2.

## 1. Architecture as found

| Area | State |
|---|---|
| Framework | Next.js 14 App Router, React 18, TypeScript (strict typecheck clean) |
| DB / ORM | Prisma 5, SQLite `prisma/dev.db` (118 models). Only 2 migrations; the base schema came from `db push`. `migrate status` reports in sync. |
| Auth | Custom JWT (`src/lib/auth.ts`), cookie `anilog_token` or Bearer. User + role re-read from DB per request. |
| Authorization | Platform RBAC exists (`User.role`, `src/lib/roles.ts`, `requireRole`/`hasMinRole`). Per-community roles on `CommunityMember`. |
| API | ~240 route handlers under `src/app/api/**`. No shared response envelope enforced (mixed shapes). |
| Client state | React contexts (`AuthContext`, `LibraryContext`, `ToastContext`, `SocketContext`); library is server-backed. |
| Providers | Centralised in `src/lib/providers/**`, `src/lib/jikanService.ts`, `src/lib/engine/news/adapters/**`. No UI component calls a provider directly (verified by grep). |
| Media | `src/lib/storage/**` — R2 provider via `@aws-sdk/client-s3`, local fallback, magic-byte validation, sharp re-encode to WebP. Credentials server-only. |
| Background jobs | None. Sync/news/schedule run inline or via manual scripts. `DeadLetterQueue` holds 4,615 unretried Jikan failures. |
| Tests | No test runner. ~50 ad-hoc `src/lib/test_*.ts` scripts that write to `dev.db` — the source of the fixture pollution in §3.2. |
| Lint / type | `tsc --noEmit` clean. `next lint`: 0 errors, 24 warnings. |

## 2. Findings by severity

### CRITICAL

1. **Forgeable sessions when `AUTH_SECRET` is unset.** `auth.ts` falls back
   to a JWT secret string committed in the repo. Any deployment without the
   env var accepts tokens anyone can mint for any user id.
2. **Unauthenticated catalog writes.** `POST /api/sync` (full catalog sync),
   `POST /api/admin/anime/import` (start/reset import job) and
   `POST /api/admin/images` (bulk "repair" of catalog image URLs) have no auth
   check at all. `GET /api/admin/data`, `/admin/data-sources`,
   `/admin/anime/import` expose internal job/provider state likewise.
3. **User ratings overwrite the provider score.**
   `recalculateAnimeAggregates()` writes OTAKUVA's Bayesian user aggregate
   into `Anime.score`/`scoredBy` — the provider-sourced columns. It runs on
   every *read* of a rating summary too. Five real anime (Frieren, FMA:B,
   Attack on Titan, Monster, Demon Slayer) now show e.g. "7.23 from 1 rating"
   in place of their MAL score; the original value was never stored anywhere
   recoverable.
4. **Fabricated catalog statistics.** `scripts/repair_data_integrity.ts`
   hand-typed `score`/`scoredBy` for four anime (e.g. Attack on Titan
   "9.17 / 2,750,000") with no provider fetch; ~10 seed-origin anime carry
   similar round, hand-entered `scoredBy` values (987,400, 780,000, …).
5. **Fabricated schedule.** The broadcast-slot schedule derivation assumes
   "next episode = highest imported episode + 1" and stamps the row
   `isVerified: true`. 7 of 8 live rows are wrong: One Piece "episode 801"
   (the last imported episode aired in 2017), Anpanman "episode 1", etc.
6. **Fabricated content on the anime detail page, for every title.**
   `WhereToWatch` lists Crunchyroll/Netflix/Prime regardless of the anime
   (there are zero availability rows in the DB); `PersonalizedRecommendations`
   is a fixed list with invented reasons shown to everyone;
   `CommunityTeaser` shows fake threads with 1,240/856 replies;
   `UserCollectionsCard` shows fake lists with save counts;
   `UserActivityCard` invents "14 episodes watched";
   `ProductionTimeline` invents a manga serialisation and committee
   green-light date from the air year.
7. **Fabricated activity on real user profiles.** `ActivityTimeline` shows
   five invented actions ("rated Frieren 10", "joined Fantasy & Magic
   Worldbuilding") on any profile with no activity yet.

### HIGH

8. **Private community content readable by anyone.**
   `GET /api/communities/:slug/posts`, `GET /api/communities/:slug/members`,
   `GET /api/discussions/:id` and the global `GET /api/discussions` list never
   call `canViewCommunity`. Chat/channels do. (`POST` comment/post paths go
   through the engine, which does check membership.)
9. **Private lists leak; list creation unauthenticated.**
   `GET /api/lists?userId=X` returns that user's `PRIVATE` lists.
   `POST /api/lists` writes every list as the hardcoded `user_default`.
10. **`/api/stats` answers anonymous callers with `user_default`'s stats**
    instead of 401.
11. **Test fixtures in canonical tables.** 2 fixture anime
    (`mind-paradox-1788674684858`, `daily-laughs-1788674684858`, posters on
    example.com), 1 fixture studio (`MAPPA AI Intelligence 1788674684858`),
    ~17 test accounts, 3 test communities from previous verification runs.
    Some real-looking accounts have reviews/ratings on the fixture anime.
12. **News review queue is ADMIN-only** (`role !== 'ADMIN'`), so
    `NEWS_EDITOR` and `SUPER_ADMIN` get 403 on the one screen built for them.

### MEDIUM

13. Fallback literals presented as data: `AnimeHero` (year → 2024,
    status → Finished), `SpotlightHero` (year → 2026, "24 Episodes"),
    `QuickViewModal` (year → 2024), `DiscoverMoreSection` ("23 verified
    studios"; DB has 98).
14. Defaults that assert verification nobody performed:
    `NewsArticle.verificationStatus = "VERIFIED"`,
    `AiringSchedule.isVerified = true`, `ingestScheduleEvent` defaulting
    `isVerified` to true, `Review.overallSentiment = "POSITIVE"` with
    confidence 1.0, studio backfills auto-marking `VERIFIED`.
15. `recalculateAnimeAggregates` loads every rating on the platform to
    compute one global mean, on every summary read.
16. `Community.memberCount` drifts from actual active members
    (`notify-scope-check`: stored 1, actual 3).
17. 21 components with no importers, several containing fabricated data
    (`AnimeInfoTable`, `AnimeQuickInfo`, `TopCommandBar`, …).
18. 4,615 Jikan failures in `DeadLetterQueue`, never retried.

### LOW

19. `hasMinRole` sibling semantics are fine, but the `REQUEST_TO_JOIN`
    visibility means "readable by all, posting needs approval". That is a
    product decision the charter leaves open — flagged, not changed.
20. Upload validator accepts AVIF (charter says JPG/PNG/WebP); output is
    always re-encoded WebP so the risk is low.

## 3. Root causes

### 3.1 The recurring pattern
Most critical findings share one cause: **a UI or script that could not
find real data substituted plausible-looking data instead of showing the
gap.** Components shipped with "demo" fallbacks that were never removed;
scripts "repaired" data by typing values from memory; the schedule deriver
guessed an episode number. The fix in every case is the same rule the
charter states: missing stays missing — render an honest empty state, or
don't render the section.

### 3.2 Earlier reports
`OTAKUVA_DATA_INTEGRITY_REPORT.md` describes the hand-typed scores in §3.1
above as "canonical" and the 30 MediaAsset rows it inserted as "verified with
SHA-256 checksums". The scores were not fetched from any provider. Treat that
report as unreliable.

### 3.3 Flow traces
- **Score overwrite:** rate anime → `POST /api/anime/:id/rating` →
  `submitUserRating` → `recalculateAnimeAggregates` → `prisma.anime.update
  ({score: bayesian, scoredBy: count})`. Also: any page load →
  `GET /api/anime/:id/rating-summary` → `getRatingSummary` → same write.
- **Schedule:** `sync_broadcast_schedule.ts` / admin sync →
  `syncFromBroadcastMetadata` → `episode.findFirst(max number) + 1` →
  `ingestScheduleEvent({isVerified: true})`. Episode import for long
  runners stops at old pages, so max number is years stale.
- **Private posts:** anonymous `GET /api/communities/secret/posts` → community
  lookup → `discussion.findMany({communityId})` — no visibility branch.
